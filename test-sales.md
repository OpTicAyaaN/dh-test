# Questions that tend to come up in sales demos

- **Can the docs stay current without a manual cleanup pass every time the product changes?** Teams raise this because they want a process that reduces repeat maintenance work and keeps published information aligned with product updates.
- **Does the system fit into the tools the team already uses?** Buyers ask this because they want documentation work to connect with existing notes, transcripts, and documentation sources instead of forcing a separate workflow.
- **Will the output still sound polished enough for customer facing use?** This comes up because teams want to save time without giving up quality, consistency, or credibility in published material.
- **Can the system turn messy source material into something usable for a real workflow?** Prospects raise this concern because notes and transcripts often contain useful details, but they usually require too much effort to organize by hand.
- **How much review work does the team still need to do before publishing?** This question reflects concern about risk, accuracy, and whether automation truly removes enough effort to justify adoption.
- **Can the system support a small documentation team with a large volume of work?** This comes up because lean teams want to cover more updates, requests, and follow up work without adding headcount.

# Questions that may come up in future sales demos

- **How does the system help technical writers preserve voice and structure across many documents?** This question is likely because documentation teams often care as much about consistency and standards as they do about speed.
- **What controls exist before new content reaches a public docs site?** This is likely because teams that publish customer facing material need confidence that review and approval still stay in human hands.
- **Can the system support product launches, release updates, and sales follow up from the same source material?** This may come up because buyers often look for one workflow that serves several content needs instead of a narrow point solution.
- **How well does the system handle incomplete notes or uneven meeting transcripts?** This question is likely because source material often varies in quality, and buyers want to know how much cleanup work remains.
- **Can the system highlight gaps in what a team has documented or discussed with prospects?** Technical writers are likely to ask this because they often need help spotting missing explanations before those gaps create repeat questions.
- **How easily can a team adapt the output for different audiences such as sales, support, and documentation?** This is likely because the same source discussion often needs several versions for different internal and external uses.

# Best selling points

- Reduces the time required to turn notes and transcripts into usable documentation and sales support material.
- Helps small teams cover more content work without expanding headcount.
- Connects source material and documentation work so important details do not get lost between conversations and publishing.
- Produces organized output from messy inputs, which helps teams move from raw discussion to customer ready material faster.
- Supports a more consistent documentation process, which reduces the scramble that often follows product changes and customer requests.
- Gives sales and documentation teams a clearer path from buyer conversations to follow up content.

# Biggest feature asks

- Stronger controls for review and approval before publishing, driven by the need to manage risk and protect content quality.
- Better support for maintaining a consistent voice and structure, driven by the need to keep documentation credible across many contributors and documents.
- More flexible ways to adapt one source into several outputs, driven by teams that need sales, support, and documentation material from the same conversations.
- Clearer handling of incomplete or inconsistent source material, driven by the need to reduce cleanup work when notes and transcripts vary in quality.
- Better visibility into missing topics and unanswered customer concerns, driven by teams that want to catch documentation gaps before they slow evaluation or adoption.
